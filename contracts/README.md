# Contract validation boundary

The generated JSON Schemas are interoperability aids generated from the frozen typed models.
They are exact generated bytes, but standalone JSON Schema validation is not equivalent to the
Python typed validator.

The typed validator additionally enforces invariants that draft JSON Schema cannot express
portably here: real UTC/calendar values; provenance claims derived from working/HEAD hashes and
status; exact set membership and uniqueness; risk boundaries re-derived from the pinned bundled
tzdb (including gap/fold policy, offsets, labels, and adjacency); reason-specific gap evidence;
checkpoint full-body canonical-byte digests, natural-key identity/order, geometry, states, counts,
and bounds; and tick exact-replay eligibility derived from all persisted qualification facts. Consumers must run a
version-matched typed validator and canonical hash verification before treating an artifact as
valid. In Phase 0, even a valid capability artifact remains an untrusted claim unless a
gate-specific verifier re-hashes it and validates an approval signature against a trust root.
